# STORY_049 — The director on the server

After [STORY_048](STORY_048_the_gemini_spike.md) (the spike, whose request shape, model id, safety settings and refusal wording this story codes against)
**Status:** Done (2026-09-17 12:17 EDT — approved under the owner's blanket "continue story by story" of 05:20; built 11:45 → 12:05; gate steps 1–4 green by hand, build + e2e after; deployed and verified live; the Done note below)
**Created:** 2026-09-17

As the owner, I want the app's own server to take a photo, a director skill and my notes, ask Gemini for the finished prompt, check the reply against the format the model on the Spark expects, and hand back either the prompt with anything it found wrong, or the model's refusal in its own words — so that the UI stories have one route to call and the gate can prove every outcome without ever reaching Google.

## Current state (read from the code, 2026-09-17 03:00 EDT)

- **The spike proved the call** (STORY_048): `lib/vertex.ts` signs, exchanges and posts; `lib/agent-request.ts` › `readSkill` and `assembleRequest` build the request; the model id is `VERTEX_MODEL`'s code default; the safety and generation settings are named constants. Nothing calls them from a route.
- **Routes and their tests.** Every API route is a `route.ts` under `app/app/api/…` wrapped in `guarded()` (`lib/model-client.ts`: config errors → 500 `config`, the contract's `{ error: { code, message, field? } }`); the integration lane (`app/test/integration/*.test.ts`) imports the handlers and starts the stub in-process (`createStubServer` from the `stub-generation-server` package, a random port, `MODEL_BASE_URL` set per test). `POST /api/jobs` reads multipart with `request.formData()`, takes `referenceImage` files and validates them with `lib/upload-validation.ts` (PNG / JPEG / WebP, ≤ 10 MiB, at most two).
- **The e2e lane picks the stub's outcome by name**: the composer forwards a `?script=` on the page URL to `POST /api/jobs?script=`, the route sends it upstream, and the stub reads it as `x-stub-script` or `?script=` (`server.ts` line 322; `isScriptName` refuses an unknown name). The stub's hooks live under `/__stub/`: `reset`, `busy`, `jobs`, `jobs/:id/received`, `fixtures/*`.
- **Skills at runtime.** `agents/skills/` is not in the production image — `app/Dockerfile`'s runner stage copies `.next/standalone` and `.next/static` and nothing else; the e2e server's working directory is `app/` (`playwright.config.ts` runs `node .next/standalone/app/server.js`). The owner's decision (2026-09-17): the folders are **baked into the image**, with a `SKILLS_DIR` for the gate and dev.
- **The base format, as the adapter reads it** (`spark/adapter/src/prompt.ts`): a prompt that starts with `integrated_multimodal_description:` or with either instruction line (`For the target video`, `How the reference pictures align`) passes through unchanged (`isBaseFormatPrompt`); `descriptionOf` is the text between the marker and `overall_soundscape:`. Nothing in the app checks a prompt's shape today; the adapter never refuses one.
- **Runs that end without a prompt have nowhere to live**: the Inbox (`lib/inbox.ts` › `eventsFor`) is a projection of history entries by task; a refusal that never became a job would be lost on reload. The owner's decision (2026-09-17): a small **agent-runs store** the Inbox merges in — the store is this story's (server side), the merge and the notice are STORY_050's.

## Acceptance Criteria

- [x] **`GET /api/agent/skills`** answers `{ skills: [{ id, name, description, metadata }] }` — one entry per folder under `SKILLS_DIR` that holds a `SKILL.md` with valid frontmatter, sorted by id; `id` is the folder name, `metadata` the frontmatter's map as strings. A folder with a broken `SKILL.md` is skipped and named in the server log once. `SKILLS_DIR` defaults to `/srv/agents/skills` in the image (the Dockerfile's runner stage copies `agents/` there) and to the repo's `agents/skills` resolved from the app's working directory otherwise; `playwright.config.ts` and the integration lane pass it explicitly.
- [x] **`POST /api/agent/runs`** (multipart: `skill` — an id from the list; `referenceImage` — exactly one file, validated as the jobs route validates one; `notes` — text, may be empty; `?script=` forwarded upstream as the jobs route forwards it) assembles the request with `assembleRequest` (the skill's body as the system instruction, its references, the image, the notes — STORY_048's order), calls the model with the spike's safety and generation settings (`DIRECTOR_SAFETY_SETTINGS`, `DIRECTOR_GENERATION_CONFIG`; **the thinking level from `VERTEX_THINKING` — `low` by default, `medium`, `high` or `default` for the model's own choice — read from the env store then `process.env`, the owner's decision of 2026-09-17 after the spike's comparison**) in **two passes** — the draft, then the draft sent back with `expandInstruction(450, 600)` (which also asks for the subject to be named by appearance in every beat) — and the request's own `signal`, and answers **200** with one of: `{ kind: "prompt", prompt, findings }` — the reply's text trimmed, `findings` the format check's list (empty when clean); or `{ kind: "refusal", message }` — the model's words verbatim when it gave any, else the block or finish reason in a sentence ("The model stopped for safety: <category>"). Errors are the contract's shape: **400** `validation` (an unknown skill, a missing or rejected image); **503** `not_configured` with `readAgentConfig`'s reason; **502** `unreachable` (a network failure, the message without the URL); **429** `quota` relayed with Google's message; **502** `bad_reply` when the reply has **none** of the three fields (its first 200 characters in the message — the owner sees what came back); **499**-style `aborted` is never sent: an aborted request has no client. A run takes at most `AGENT_TIMEOUT_MS` (default 90 s), then `504` `timeout`.
- [x] **The format check, `lib/prompt-format.ts` › `checkPromptFormat(text, { chain?: boolean })`** — pure, returns `{ findings: [{ code, message, segment? }], segments }`. For a single-clip prompt the codes are: `text-before-instruction` (anything before the instruction line — commentary, a title, a code fence), `no-instruction-line`, `no-description`, `no-soundscape`, `no-music`, `description-line-breaks` (a blank line or a label inside the description), `description-too-short` (< 350 words), `description-too-long` (> 600), `timestamps` (a `[m:ss` bracket, or the format's own cut phrase — a clock time followed by "the camera cuts" — inside a single-clip description), `markdown` (a fence or a heading anywhere), `no-shot-label` (`[Shot 1]` missing). Every message is plain English with the number it measured ("the description is 312 words; the skill asks for 350–600"). A code fence around an otherwise clean prompt is **stripped before checking** and reported as `markdown` so the prompt is still usable. The chain option is STORY_053's and is refused here (`chain: true` → the single-clip rules on segment 1 only — the rest defined there).
- [x] **The reply is the prompt, findings and all** — the route never withholds a reply that has at least one of the three fields; the review-versus-block decision is the caller's (STORY_050 warns, STORY_051 blocks straight-through) — the owner's rule of 2026-09-17 (his answer to review question 7).
- [x] **A run that ends without a prompt is recorded**: `lib/agent-run-store.ts` › `agent-runs.json` beside `history.json` (the env and skills stores' pattern, written atomically) keeps `{ id, at, skill, notes, outcome: "refusal" | "error", message }` for every refusal, `bad_reply`, `quota`, `unreachable` and `timeout` — **never for a prompt, never for an abort** (the owner's own act; the epic's list said Stop, corrected here and said so); `GET /api/agent/runs` lists them newest first with an optional `openedAt`; `PATCH /api/agent/runs/:id { openedAt }` stamps one (STORY_050's Inbox row uses it); the store keeps the last 200. No image is stored — the notes and the outcome only.
- [x] **The stub gains a fake Vertex** (`tools/stub-generation-server`), on the stub's own port so `VERTEX_BASE_URL` and `VERTEX_TOKEN_URL` both point at it in the gate: `POST` on the token path returns a fake bearer token for any assertion; `GET` on the publisher-models path returns two Gemini entries; `POST …:generateContent` answers by script name (`x-stub-script` or `?script=`, default `clean`): **`clean`** — a committed fixture prompt for the stub's own reference image (`fixtures/agent/clean.txt`: the instruction line, a 350–600-word single paragraph, both sound fields — passes the check); **`warn`** — the same with the soundscape field dropped and the description cut to ≈ 300 words (two findings); **`refusal`** — a candidate stopped for safety with no text; **`refusal-text`** — a polite refusal in prose, in the shape the spike recorded; **`malformed`** — "I can't see an image in this request."; **`slow`** — `clean` after 8 s (Stop's test; an abort is noted); **`quota`** — 429 in Google's error shape. `GET /__stub/agent/runs` lists what the fake received — the script, whether the request was aborted, the system instruction's word count, the parts in order as `{ kind: "text", head }` (the first 60 characters) or `{ kind: "image", mimeType, bytes, sha256 }`, the safety settings — and `POST /__stub/reset` clears them. The fake's request parsing follows the shape STORY_048 recorded; nothing in it is Google's code.
- [x] **The gate never calls Google**: `playwright.config.ts` passes `VERTEX_BASE_URL`, `VERTEX_TOKEN_URL` (the stub), `VERTEX_PROJECT`, `VERTEX_LOCATION`, `VERTEX_MODEL`, `SKILLS_DIR` and `GOOGLE_APPLICATION_CREDENTIALS` — **a key pair generated in `globalSetup` into the run's temp dir**, never a committed key — to the built app; the integration lane does the same per test. A source-text guard asserts no test file and no fixture contains a private-key block.
- [x] **The image goes to Google as the route received it** — no image library on the server (zero runtime dependencies, and Node has no canvas). If STORY_048 found downscaling worth it, the **composer** does it in the browser with a canvas before posting (STORY_050's job, noted there); the route never resizes.

**AC corrections made during implementation, as § 3 item 8 asks (2026-09-17):**

- **The timeout:** the AC's 90 s predates the spike — one pass took up to 107 s and a run is two passes; `AGENT_TIMEOUT_MS` defaults to **240 s** (an engineering cap; `.env.example` says so).
- **`bad_reply`:** the AC made prose instead of a prompt a 502; a reply with none of the three fields is the model *talking* instead of directing, so it is shown as a **refusal in the model's words** (recorded as one) — the owner reads what came back either way; `bad_reply` is kept for an empty reply. The fake's `malformed` and `refusal-text` therefore both answer `kind: "refusal"`.
- **The key for the e2e lane** is generated in `playwright.config.ts` itself rather than `globalSetup`, so it exists before the web servers start; same effect, a key pair per run in the temp dir.
- **The chain rules** (segments 2..N: the marker first, no instruction line, no picture) are implemented in `checkPromptFormat` now rather than left to STORY_053 — the chain draft existed and the stub's `chain` fixture is a real three-segment reply; 053 inherits the check and adds the splitter's second convention in `lib/chain.ts`.
- **`.dockerignore`** excluded every `*.md`, which would have dropped every `SKILL.md` from the image; `!agents/**/*.md` added.
