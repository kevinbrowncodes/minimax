## Technical Notes

- **Why the base files are copied and not mounted:** the owner's decision (SPIKE_001 › Decisions 6, 14:10): total isolation — the NSFW container can be moved, rebuilt or deleted with its whole models directory and never opens an SFW path. The copy is local (`cp --reflink=auto` on the NVMe, minutes; the filesystem's reflink support checked and said in the note), never a second download.
- **The one-shot copy needs to see `models/`:** the `fetch-nsfw` service mounts `${SPARK_DATA}/models` read-only at `/comfy/models-sfw` for the duration of the copy only; the long-running `comfyui-nsfw` service never mounts it. Say so in a comment beside the service.
- **The manifest is TSV, not JSON**, so `bash` and `sha256sum -c` can read it without a parser; a comment line per row explains what the file is and where it came from (the Civitai model id and version id, or the Hugging Face repo and path). The spike's session already read the SHA-256s of six of the files (Current state); the story re-reads all of them the day the manifest is written (CLAUDE.md § 3 item 8 — live state).
- **The switch is host-side only.** Nothing in a container runs `docker`; `run.sh` is the only place that knows both containers, and its refusal reads ComfyUI's `/queue` on the other port. The adapter learns which is up by probing (STORY_064).
- **`smoke.sh` on 8189:** the script's `COMFY_URL` is set from `lib.sh`; this story lets `COMFY_URL` be overridden from the environment (one line) so the same smoke test can hit either container. It runs the SFW template deliberately — the NSFW container must first prove it is the same ComfyUI before any LoRA is judged.
- **Memory:** one at a time, so nothing changes in the arithmetic; the NSFW container's idle footprint is recorded because the epic's "both up" story, if ever, starts from it.
- Not in this story: the adapter (064), the UI (065), the nsfw template's LoRA chain (064 — this story's `verify.sh --nsfw` reads the manifest, not a template).
