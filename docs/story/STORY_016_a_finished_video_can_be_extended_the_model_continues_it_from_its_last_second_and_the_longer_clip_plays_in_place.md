**Created:** 2026-09-13 · promoted from [BACKLOG_001](../backlog/BACKLOG_001_a_finished_video_can_be_extended_from_where_it_ends.md)

As the owner, I want an **Extend** action on a finished video that lets me describe what happens next and choose how many seconds to add (10 by default), so that the Spark continues the clip from its last second — motion and sound unbroken — and the longer video plays, downloads and appears in Assets like any other, so that a piece can grow past what one run makes in the time I am willing to wait.

## Current state

The task page's result card offers Download and Copy prompt (STORY_014). The composer starts a new job from a prompt and up to two reference images (STORY_013). The adapter builds one graph, `MiniMaxH3ImageToVideo` on the **FL2VA** checkpoint with optional first/last frame (STORY_006); the Ref2VA checkpoint is not on the Spark. Nothing loads a finished video back into a generation. The owner's first real clip (10 s, 2026-09-12) is the one he asked to extend.

**What MiniMax says, read 2026-09-13 in [docs/references/](../references/README.md):**

- MiniMax's full-reference prompt guide defines the task type **`video continuation`** — *"New content continues, extends, resumes, or transitions from an existing source video"* — with the source passed as **`<Video N>`**, *"a reference video that provides an editing source, continuation starting point, or whole-video temporal structure"*, and its sound as `<Audio N>` under `audio reference` or `audio reuse` ([prompt-guides/VIDEO_PROMPT_WRITING_GUIDE_ref_en.txt](../references/prompt-guides/VIDEO_PROMPT_WRITING_GUIDE_ref_en.txt) §2.3, §3). That is **full-reference mode, i.e. the Ref2VA checkpoint** (model card: "H3-Base-Ref2VA — omni-reference mode … videos ≤ 3 clips, each 2–15 s"). In MiniMax's hosted API the same thing is a `role: reference_video` item on the v2 create endpoint ([api-reference/minimax-api_video-generation-v2-create.md](../references/api-reference/minimax-api_video-generation-v2-create.md)); the API has no separate "extend" call and caps one task at 15 s, so the joining is the caller's.
- ComfyUI exposes exactly this: `MiniMaxH3ReferenceToVideo` takes `ref_videos` ("reference video frames at 24 fps (2–15 s)") with `ref_video_audios`, cuts each clip down to the model's 17k+5 grid, shows it to the text encoder at 2 fps and to the DiT as latents that ride through every step ([comfyui/comfy_extras/nodes_minimax_h3.py](../references/comfyui/comfy_extras/nodes_minimax_h3.py) `execute`). On top of it, `MiniMaxH3AddGuide` anchors a clip at a frame — ComfyUI's documented continuation recipe: *"feed the first 22 frames of an existing video plus its audio into a `MiniMaxH3AddGuide` at frame 0, and the model generates the continuation of both streams"* ([comfy-docs/minimax-h3-native.md](../references/comfy-docs/minimax-h3-native.md), PR [#15439](../references/comfyui/PR-15439.md)); Comfy-Org's own Multiframe template stacks Add Guide on Reference to Video, which is the combination this story uses. A community workflow attached to PR #15375 chains such segments "for unlimited length videos", cutting the 22-frame overlap at the join ([PR15375_droz_MiniMaxH3_BasicMaskedExtension_v1.4.json](../references/comfyui/examples/PR15375_droz_MiniMaxH3_BasicMaskedExtension_v1.4.json)).
- Every node needed is in our ComfyUI image (v0.35.1, commit 856a922; checked by name 2026-09-13); `LoadVideo` reads a file from ComfyUI's output directory when the name ends in ` [output]`, so the finished clip needs no upload; Autogrow inputs are addressed by dotted path in the API format (`ref_videos.ref_video_0`; `comfy_api/latest/_io.py` `finalize_prefix`).
- The Ref2VA weights at our precision, `diffusion_models/minimax_h3_ref2va_int8_convrot.safetensors`, are **34.0 GB** on Comfy-Org/MiniMax-H3 (same license, same file family as the FL2VA file we serve); the Spark's data volume had **1.1 TB free** on 2026-09-13, so the download rule (≥ 300 GB free) is met.

## Acceptance Criteria

**Contract — [docs/contracts/job-api.md](../contracts/job-api.md) v1.1 (both servers):**

- [ ] `POST /jobs` accepts an optional `continueFrom: <jobId>`. With it, the job is an **extension** of that job: `durationSeconds` is the number of seconds **added**, `ratio`, `resolution` and `model` must equal the source's, and no `referenceImage` part may be sent. `GET /jobs/:id` echoes `request.continueFrom`. The result is the **joined** video (source followed by the continuation), and `result.durationSeconds` is the joined length.
- [ ] `GET /capabilities` gains `extension: { durationsSeconds: { min: 4, max: 14, step: 1, default: 10 }, maxSourceSeconds: 30 }`.
- [ ] Errors: `continueFrom` that is not a `done` job of this server, or whose output file is gone → `400 validation` (field `continueFrom`); a source longer than `maxSourceSeconds` → `400 unsupported_option` (field `continueFrom`); `durationSeconds` outside `extension.durationsSeconds` → `400 unsupported_option` (field `durationSeconds`); a differing `ratio`/`resolution`/`model` → `400 validation` (that field); a reference image → `400 validation` (field `referenceImage`).

**Serving config (`spark/comfyui/`):**

- [ ] `fetch-h3.sh` also fetches `diffusion_models/minimax_h3_ref2va_int8_convrot.safetensors` (34.0 GB; size-verified against Hugging Face like the other files; only when ≥ 300 GB are free, as today); `verify.sh` and the adapter's start-up check know the file. `spark/README.md` and the root README's Running the Model list both checkpoints and what each serves (FL2VA: fresh jobs; Ref2VA: extensions).

**Adapter (`spark/adapter/`):**

- [ ] **The prompt.** `continuationPrompt(prose, sourceSeconds)` turns the owner's prose into MiniMax's six-section full-reference text ([prompt-guides/…_ref_en.txt](../references/prompt-guides/VIDEO_PROMPT_WRITING_GUIDE_ref_en.txt)): `subject_definitions` (`<Video 1>` is the source video the target continues from; `<Audio 1>` is its synchronized soundtrack, referenced for continuity), `summary` beginning `[video continuation + audio reference]`, `retention_analysis` (`<Video 1> (continuation source): fully_preserved - …`; `<Audio 1>: reference - …`), `detailed_description` (one style line stating the target continues directly from the last frame of `<Video 1>` with its framing and lighting, then `[Shot 1]` followed by the prose verbatim), `overall_soundscape` (continues `<Audio 1>`'s ambience), `non_diegetic_music` (only what the description asks for; none otherwise). A prompt that already begins with `subject_definitions:` is sent unchanged. History and the status body keep the owner's prose; the wrapped text goes to ComfyUI and is logged.
- [ ] **The graph** for an extension (`buildGraph` with a continuation) uses the Ref2VA checkpoint (`unet.unet_name = minimax_h3_ref2va_int8_convrot.safetensors`) and replaces `cond` with `MiniMaxH3ReferenceToVideo` { `clip`, `vae`, `audio_vae`, `prompt` = the wrapped text, `width`, `height`, `length = segment`, `ref_image_size: "match"`, `ref_videos.ref_video_0` ← the source's **last 107 frames** (`LoadVideo` of `"<subfolder>/<filename> [output]"` → `GetVideoComponents` → `ImageFromBatch` `batch_index = sourceFrames − 107`, `length = 107`; 107 = 17·6+5, ≈ 4.5 s, so the node cuts nothing), `ref_video_audios.ref_video_audio_0` ← the source's last 107⁄24 s of audio (`TrimAudioDuration` `start_index = sourceSeconds − 107⁄24`, `duration = 107⁄24`) }; then `MiniMaxH3AddGuide` { `positive` ← the reference node, `latent` ← its latent, `vae`, `audio_vae`, `image` ← the source's **last 22 frames**, `audio` ← its last 22⁄24 s, `frame_idx = 0` } whose output feeds the `BasicGuider`; the join = source frames followed by the segment **from frame 22 on** (`ImageFromBatch` `batch_index = 22`, `length = segment − 22`) via `ImageBatch`, and source audio followed by the segment's audio from 22⁄24 s on (`TrimAudioDuration`) via `AudioConcat` (`after`), into the existing `CreateVideo` → `SaveVideo`; the poster is frame 0 of the joined clip. `REQUIRED_CLASSES` gains `LoadVideo`, `GetVideoComponents`, `MiniMaxH3ReferenceToVideo`, `MiniMaxH3AddGuide`, `ImageBatch`, `TrimAudioDuration`, `AudioConcat`. A fresh job's graph is unchanged (FL2VA, `MiniMaxH3ImageToVideo`).

New frames per request: +4 s → 124 − 22 = 102 (4.25 s); +5 s → 158 − 22 = 136 (5.67 s); **+10 s → 277 − 22 = 255 (10.6 s)**; +14 s → 362 − 22 = 340 (14.2 s, the model's trained ceiling of 362 frames — the reason `max` is 14).

## Departures from the reference

- The Extend control does not exist in the reference captures, and MiniMax's API caps a task at 15 s with no extension call; the control is an owner-requested improvement (2026-09-13). If the reference turns out to have one, the visual rules of this story change to match it, not the mechanism.
- The mechanism is MiniMax's (full-reference `[video continuation]` on Ref2VA); two things are ours because MiniMax's platform does not do them: the 22-frame anchor at frame 0 that makes the seam pixel-exact (ComfyUI's documented recipe), and the in-graph join that returns one clip.
- No reference images while extending: the source's last seconds are the reference. A last-frame target for an extension (`[video continuation + keyframe completion]` in MiniMax's terms) is a later story.
- The result of an extension is the joined clip, not the new segment alone; the source stays in history and Assets untouched.

## Technical Notes

- **Two checkpoints on disk, one loaded at a time.** FL2VA serves fresh jobs, Ref2VA serves extensions; ComfyUI swaps the 34 GB DiT when a job of the other kind arrives (a minute or two from NVMe with `--disable-mmap`), so an extension after a fresh job pays that once. Same text encoder and VAEs for both.
- **Why the reference is 107 frames and the anchor 22.** The reference clip gives the model the source's identity, scene and motion in MiniMax's own terms; its tokens ride through every sampling step, so its length costs time and memory (107 frames ≈ 44 % of a 10 s generation's video tokens) — long enough to carry motion, short enough to measure. The anchor pins the segment's first 0.92 s to the source's last 0.92 s so the join is exact; those 22 frames are then cut from the segment. 22 is the smallest clip length with motion in it (5 is a still, in effect). Both numbers are constants in `mapping.ts`, changed only with a measurement.
- **Memory**: `GetVideoComponents` holds the whole source as float frames (≈ 12.4 MB per 1344×768 frame) and `ImageBatch` allocates the joined batch beside it: a 30 s source ≈ 9 GB, transiently 2× at the join, plus the reference and anchor latents, on top of the ≈ 68 GiB generation peak measured for FL2VA — inside the 121 GiB with margin; a 60 s source would not be. Hence `maxSourceSeconds: 30` for this story; lifting it means joining outside the graph (a later story). Ref2VA's own peak is unmeasured until the manual verification.
- **Time**: one generation of `segment` frames on Ref2VA with a 107-frame reference. FL2VA measured 51 min for 10 s on 2026-09-12; expect more for +10 s here, and write down what it was.
- **Adapter plumbing**: `createJob` resolves `continueFrom` in the `JobStore` (done, file present via `safeOutputPath`, `frames` known), then `buildGraph(template, request, [], { continuation: { file, frames, prompt: continuationPrompt(prose, frames / 24) } })`. `result.frames` is added to `JobResultFiles`; `finalize` derives `durationSeconds` from it. The status body's `request` includes `continueFrom` when set. The Autogrow inputs are written with their dotted ids (`ref_videos.ref_video_0`, `ref_video_audios.ref_video_audio_0`).
- **Stub**: `continueFrom` is stored on the job and echoed; its "done" check uses `stateOf`; no new script is needed — the usual scripts choose the outcome of the extension.
- **UI state**: `ComposerState` gains `extend?: ExtendSource`; actions `extend-from` (sets ratio/resolution/model from the source, sets `durationSeconds` to `extension.durationsSeconds.default` clamped into the range) and `clear-extend`; `ratio`/`resolution`/`model` actions are no-ops while extending; `add-images` is refused; `paramsLabel` renders `+Ns`. `buildJobRequest` always sends JSON with `continueFrom` in extend mode. `Composer` takes `extend?: ExtendSource` and `onStopExtending` from the task page, which owns the "extending" flag (set by the Extend action or `?extend`). `HistoryEntry` gains `continuesFrom?: { id, title }` written by the jobs route.
- **Capabilities**: `Capabilities.extension` is optional in the UI's type; a server without it hides nothing today (both servers have it), and the composer's duration group falls back to the plain range if it is missing.
