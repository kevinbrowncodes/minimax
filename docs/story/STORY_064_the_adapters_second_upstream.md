## Technical Notes

- **Two upstreams, one ComfyUI client class.** `comfy.ts` is instantiated twice (url, output dir); `server.ts` keeps a small map `{ modelId → { client, template, requiredClasses, state } }` and the existing single-upstream code becomes the map's first entry — the diff should read as "today's path, parameterised by model", not a fork. The websocket progress channel (`events`) is per upstream too.
- **The job store** gains `model` per job (it already stores the request, which carries it) and reads the upstream from it on every later call; jobs stored before this story have `model` absent → the SFW upstream.
- **The health verification is per model and lazy** as today (`checkComfy` on the first contact); a model whose server is down is simply not ready — never an adapter start-up failure, so the SFW flow keeps working when the NSFW container is stopped (which is the normal state).
- **Extensions on the nsfw model** run the same STORY_017 masked continuation on the nsfw template's checkpoint with its LoRA chain (the template's `unet` is the chain's head, so the extension branch inherits it by construction); STORY_061's anchor likewise. The spike's row 9 proves it on the box.
- **The version numbers are "the next ones when it lands", not a claim.** STORY_062 (Probe the seed before the hour, EPIC_009, the peer session's draft) also names contract v1.6 / adapter 1.7.0; agreed with that session on 2026-09-19 17:00: whichever story lands on `develop` first takes v1.6 / 1.7.0 and the other renumbers to v1.7 / 1.8.0 at that point. This story's text says v1.6 / 1.7.0 until then.
- **The contract's `model` rule for extensions** already refuses a mismatch; the message names both models so the UI can say "this clip was drawn with the uncensored model".
- Not in this story: the UI (065), the skill (066), a GPU slot for both containers (EPIC_010 › Later).
