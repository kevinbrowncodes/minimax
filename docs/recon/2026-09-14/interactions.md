## 1. How the finished result reaches the thread

The 2026-09-12 job ("Paper boat on rain puddle", Hailuo-2.3, 6 s, 768P) **did finish** after that day's 20-minute bound. The agent had created a **scheduled task** (a cron of its own) to poll the provider; its follow-up turns appear in the thread as user-side bubbles with a **Schedules** pill (`source: "cron"` on the stored messages), and the final assistant turn is the one that carries the result:

- `GET /minimax-cloud/api/v1/session/:id/message` returns the stored thread: `messages[]` with `role`, `msg_type`, `msg_content`, `msg_id`, `turn_id`, `timestamp`, `source` (`"cron"` for the scheduled follow-ups), `thinking_content`, `thinking_duration_ms`, `finish_reason`, `usage`; plus `query_collapse_views[]` (which turns the UI collapses under "Processed N s"), `next_cursor`, `has_more`, `last_msg_id`. The 2026-09-12 shape (`msg_type` 1 = prose, 2 = step marker, 3 = to-do JSON) still holds.
- **The result card is Markdown.** The final `role: "assistant", msg_type: 1` message is the prose ("Done — paper boat, soft morning light…") followed by a block the UI renders as the **file card**:

  ```
  <deliver-assets>
  <media src="<file id>" name="<file id>.mp4" type="mp4" />
  </deliver-assets>
  ```

  `src` is a bare drive file id (no scheme, no host). The card shows `name`, the type in capitals, **Open preview** and a **More ▾** with Open preview / Download. The Work Area panel's **Deliverables** list is the same block, read from the same message. The `video-creater` plugin's own definition (`GET /minimax-cloud/api/v1/marketplace/plugins/video-creater`) carries the instruction that tells the agent to deliver through this markup — it is a convention between the plugin prompt and the thread renderer, not an API field.
- **Preview and download resolve the id on demand:** `GET /minimax-cloud/api/v1/drive/file/:id/download-url` → `{ download_url }` (a CDN URL; two calls today: the thread's Open preview and the Assets preview). The preview pane's `<video>` and the download both use it. A bare `GET /minimax-cloud/api/v1/drive/file/:id` answered **404** four times — the UI tries it first, then falls back to the download-url call.
- **Assets** lists the same file: `GET /minimax-cloud/api/v1/drive/file` → `nodes[]` with `node_id`, `name`, `file_ext`, `mime_type`, `size_bytes`, `cdn_url`, `front_page_screenshot` (the poster), `category`, `is_favorited` (the Star), `session_id` (Locate in task), `source`, timestamps; `total`, `has_more`. The filter chips and the From you / Star tabs re-query it with different parameters.
- Nothing like **extend**, **regenerate** or **edit** exists in the thread, the card's menu, the preview or the Work Area — the reference offers preview and download only. Our Extend (STORY_016/017) is a departure the story already records.

## 2. Reopening a session, as measured

| Moment | What happens |
| --- | --- |
| Recents row click | `GET session/:id` (title, status, `team_mode`, `archived`), `GET session/:id/message` (the thread, paged by cursor), `GET session/:id/queue`, `GET session/:id/input-summaries` (the user's attachments, with `cdn_url`), then the sidebar tree again. | Idle on a task page | `session/:id` and `session/:id/queue` every ≈ 37 s. App-wide, whatever the page: `commerce/get_membership_info`, `user/get_user_extra_info`, `config`, `common_config` and `bot/list` every ≈ 2.5 s; `signin/status`, `token_plan_credit`, `notifications` (the Inbox), `cron` (the Scheduled list), `plugins/enabled`, `project`, `channel`, `agent`, `skill`, `user/profile`, `preferences/pinned-items-order` and `sidebar/session/tree` (the Recents and their unread dots) every ≈ 8 s. The reference keeps its whole shell fresh by polling; none of it is video. |
| Open preview | `drive/file/:id` (404) → `drive/file/:id/download-url` → the `<video>` loads from the CDN URL. |
| Work Area toggle | No request — the panel is client state. |
| Theme switch | `Settings › General › Appearance` — a settings write (the account remembers it; a fresh context opened in the chosen theme), then `class="dark"` + `style="color-scheme: dark"` on the document element. |
