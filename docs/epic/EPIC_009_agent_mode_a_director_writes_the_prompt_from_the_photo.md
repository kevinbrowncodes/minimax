## Goal

The one step of the pipeline that still needs a person at a keyboard is the prompt: today the scene anchor and the script are written by the owner or by the assistant in a session, in MiniMax's format, from the photo. After this epic the owner attaches the photo, turns the **Agent** chip on, picks a director skill (the thirst-trap director today, the chain director by the end of the epic), types a line of notes or nothing, and presses Send: a Gemini Flash model on his own GCP project, following the skill exactly as the assistant does, writes the finished prompt and hands it back **into the composer to read and edit** — Send again and it is a job. A setting makes it straight-through (photo → prompt → job, no review); persistent **Agent instructions** carry his saved scenes, characters and house rules into every run; the chain director's reply goes out through **Send all** as a whole video. The gate never calls Google, the credential never enters the repo or the transcript, and a refusal from the model is shown where the prompt would have been — never a queued job.

## What exists today (read from the code, 2026-09-17 00:15 EDT — not from memory)

- **The skill is real and exercised.** `agents/skills/minimax-h3-director-thirst-trap/` (CHORE_012) is an [Agent Skills](https://agentskills.io/specification) folder — `SKILL.md` with frontmatter (`name`, `description`, `compatibility`, `metadata` naming the model, checkpoint, text encoder, ComfyUI and adapter versions and the verified-on date) and `references/` (the base guide, MiniMax's own I2VA example, a scene anchor that held) — validated by `agentskills validate` from a container. Written for a reader that can view the image: the assistant used it for the cove round (4 of 4 held, 2026-09-16) and the office round (5 draws, 4 of 4 real ones held, 2026-09-16). Its output begins with the instruction line, so the adapter's `prompt.ts` › `isBaseFormatPrompt` passes it to the model unchanged; since STORY_046 the adapter also reads the camera it asks for.
- **The composer has the slots the design uses, and nothing behind two of them.** `Composer.tsx`: the left slot holds `+`, the mode chip (*Video generation H3*, STORY_026), the model chip and the parameters pill; the right end holds the reference's `MiniMax-M3 ⌄` pill — inert, `aria-label="MiniMax-M3"`, opening a menu of three cloud models and a Thinking switch we cannot run (BACKLOG_006) — then *Run at…* (STORY_041) and Send, which becomes *Stop generation* while a job runs. Text mode's Send says "Text chat is not connected to the Spark yet — pick Video generation". Two or more `[0:00-` scripts in the box make a chain (`lib/chain.ts` › `splitChain`; the strip; *Send all* → `submitChain`, STORY_044); the splitter knows only that convention, not a full-format segment.

A Vertex call needs an OAuth2 access token from a service-account key: an RS256-signed JWT exchanged at Google's token endpoint — `node:crypto` does that; no Google SDK is needed.
- **The gate is model-free by construction** (CLAUDE.md § 4a): every test targets the stub generation server (`tools/stub-generation-server/`, scripted outcomes by name, `/__stub/*` hooks), reached through `MODEL_BASE_URL`; `playwright.config.ts` starts it and passes the URL to the production build. ## Rules that apply

The photos go to Google: the README says so in the agent section, and the chip's first-run text says so once.
- **The gate never calls Google.** Every unit, integration and e2e test targets the stub's fake Vertex through `VERTEX_BASE_URL`; a test that needs the real model is a manual verification in the Done note with the date, the model id and the token counts (CLAUDE.md § 3.5, § 4a). The spike's three calls and one real run per UI story are the whole of the epic's Google spend before the owner uses it.
- **A refusal is a shown message, never a job** — in review mode and straight-through alike; a chain is all clean or nothing queued (the owner's rule, kept in every story's ACs). The format check warns in review mode and blocks only straight-through — a short reply is still a prompt to edit *(rev.)*.
- **The reference's surfaces keep their meaning** (Option D's condition): the chip and the two icons are additions in the left slot; the right-hand pill names the agent's model as the reference's names its agent's; `+ › Skills` and Management › Skills mean what they mean on agent.minimax.io; Management › Agents and every other surface are untouched. Each UI story's Departures section says what was added and cites the capture.
- **One generation at a time on the Spark**, the queue's (EPIC_007); the app is rebuilt from a clean tree of HEAD; the adapter is not touched by this epic.
- **Zero runtime dependencies stay zero.** The Vertex client is `node:crypto` + `fetch`; if a story finds it needs Google's SDK, it says so in its Technical Notes before adding it, and why.
- **The model id is pinned in code and read from Vertex's list, not remembered**; Google's price per call is read from the price list the day 048 is written and carried into the README with that date.
